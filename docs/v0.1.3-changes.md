# v0.1.3 变更记录（2026-08-14）

本轮三个目标：对象移动/系统操作时的音频卡顿、7.1.x/9.1.x 左右平衡、音量平衡开关的规范核对。

## 1. 卡顿修复：输出级缓冲 20ms → 100ms

排查过程（全部有离线/在线测量支撑）：

- **+6dB `BINAURAL_MAKEUP_GAIN` 假设被证伪**：用 `01. KiLLKiSS.m4a` 真实解码离线渲染，逐样本复刻 `sda-final-peak-guard` 算法。+6dB 时 limiter 仅 4% 时间工作、最深增益衰减 -1.5dB、无深度下探；对象运动强度与平均 GR 的皮尔逊相关 0.012（无关）。脚本：`tmp/object-motion-limiter-test.mjs`。
- **worklet 回调间隙埋点**（已提交，作为常驻健康遥测）：`process()` 相邻调用墙钟间隔 >12ms 计数，tick 上报 `callbackGaps`/`callbackGapMaxMs`。本机播放中开任务管理器 + 窗口切换，零间隙、零供给不足 → 缺口不在输入侧（环形缓冲 4s 早已足够）。
- **根因定位**：输出级。实测本机 Chromium 给 `latencyHint: "playback"` 的 `baseLatency` 只有 20ms；Windows 系统级抖动（任务管理器、DWM 合成、驱动打嗝、对象移动时的渲染线程抢占）动辄 20–60ms，20ms 输出 FIFO 吸收不了就是可闻卡顿——即便 worklet 里还有 4s PCM。
- **修复**：`packages/player/src/player.ts` 三处 AudioContext 改用数值 `latencyHint: 0.1`（实测 Chromium 接受数值 hint 并给等量 `baseLatency`）。`positionSeconds()` 按 `ctx.baseLatency + 5ms`（peak guard lookahead）回拨，进度条与 3D 对象可视化对齐用户实际听到的位置，音画同步不受影响。

## 2. 左右平衡：calibration v3 双侧镜像对称化

诊断链（每层都有测量）：

- IR 资产镜像对总能量本身对称（±0.17dB 内），VBAP 增益完全镜像 → 不平衡不在电平校准。
- **全角度镜像扫描**（对象放 +θ vs -θ，比较同侧耳能量）：5.1.4/7.1.4 最大失配 1.28dB，**9.1.4 在 ±65°–95° 区间最大 4.39dB**（+80° 对象左耳比 -80° 对象右耳响 4.4dB）。脚本：`tmp/layout-mirror-sweep.mjs`。
- 根因：KU100 原始测量左右不对称。(+60,+100) 直达在左耳相干叠加 +2.43dB（建设性），(-60,-100) 在右耳 -1.97dB（破坏性）。VBAP 把同一对象分给两只音箱时，相干信号在耳膜处的叠加结果两边不对称。另：SADIE D1 原始 WAV 部分方向（+30、-45/45、±135/45）直达主瓣极性就是反的（已与 D1.zip 原始数据核对，属采集瑕疵；正中方向源 ITD 高达 27 samples，头模明显没摆正）。
- **修复（calibration v3，`sda-ku100-bilateral-v1`）**：`scripts/build-calibrated-hrtf.mjs` 在 v2 全部校准后增加对称化后处理——
  - 每镜像对（±30/±60/±100/±110/±140 el0、±45/±90/±135 el45）：按直达窗（共同到达起 4ms）相关最优的**公共符号 + 公共整数位移**对齐，取平均，-θ 侧使用镜像。正中方向双耳都给左右平均。
  - dry 与房间尾声**分别**恢复电平（尾声是扩散场，镜像对尾声互不相关，一起平均会损失房间能量；分别按镜像对几何均值目标公共缩放，保证输出逐耳精确镜像）。
  - 对称化后再做一次双耳公共整数 shift 把直达能量质心对齐回共同目标（TOF 离散 ≤1 sample）；尾声在本方向最终门控边界重新硬门控，wet 直达前缀与 dry 逐样本一致。
  - 约束遵守：每方向只施加左右共用的 sign/shift/scalar，不单独动任何一只耳朵；每方向保有自己的 ITD/ILD（镜像对均值）。无布局/歌曲专属 EQ。
- **结果**：三布局镜像扫描失配 0.00dB；真实内容全场 L/R 从 v2 的 -0.357/-0.257/+0.168dB 收敛到 v3 的 **-0.048/-0.066/-0.073dB**（5.1.4/7.1.4/9.1.4 互相差 ≤0.025dB），10s 窗轨迹三布局几乎重合。
- 验证器升级：`scripts/verify-hrtf-assets.mjs` 支持 v3——对称化 provenance 检查、镜像对能量精确交叉相等、正中双耳相等、ITD 镜像反对称 + 生理界限（不再锚定源 ITD：对称化的目的就是修正源不对称）。

## 3. 音量平衡开关：核对为 Dolby 规范行为

调研结论（官方文档/规范原文）：

- **Dolby dialnorm**（ETSI TS 102 366 §4.4.2.8 / ATSC A/52 §5.4.2.8）：`增益 dB = dialnorm - 31`，目标 -31 LUFS；dialnorm ∈ 1..31 故增益恒 ≤ 0，规范行为**只衰减**过响节目。本应用 Rust 解码器 `gain_db = -31 - dialogue_level_db` 与规范逐字一致。
- **DRC**（dynrng/compr、AC-4 DRC）是独立特性，本应用明确不启用。
- **Apple Sound Check**：官方只说"以相同音量播放所有音乐和视频"（iTunes/iPhone 用户指南），未公开目标电平或算法；网传 -16 LUFS 无官方出处。
- 结论：现有实现即为 Dolby 规范行为且已覆盖双耳 + 立体声（共享 `sda-final-peak-guard`），多声道物理输出按设计不受影响。
- 本轮补强：码流面板新增"响度"行（实时显示 dialnorm 对白电平/目标/当前衰减量），开关 tooltip 改为规范表述。KiLLKiSS dialnorm=-18 → 平衡开启时衰减 13dB。
