# 重做双耳渲染（按苹果 AVAudioEnvironment + 杜比 Atmos 双耳管线）

## 架构（杜比 BS.2127 思路 + 苹果虚拟化思路，二者殊途同归）

```
对象/床层 → VBAP 声像 → N 路虚拟音箱总线（worklet，已有）
  每路总线 → ConvolverNode(该音箱位置的 BRIR) → 立体声混合 → 输出
```

每源（对象）在进 VBAP 前应用：苹果式距离衰减（inverse 定律）+ 空气吸收低通（杜比远场 cues）。
杜比 Near/Mid/Far 用「干 HRIR ↔ 湿 BRIR 混合」实现：BRIR 自带房间早期反射，正是杜比房间 cue 的来源。

## 步骤

### 1. HRTF 资产管线（离线脚本）
- 新建 `scripts/build-hrtf.mjs`（Node，无需 Python）：下载 SADIE II **KU100** HRIR + BRIR（48kHz WAV，Apache-2.0），为 8 种布局的全部音箱方向（约 20 个位置，含仰角）选最近测量点，截取（HRIR 512 taps；BRIR 8192 taps ≈170ms 房间尾音），转成立体声 f32le 文件
- 产物：`apps/web/public/hrtf/hrtf-set.json`（清单：每位置 dry/wet 文件对 + 采样率 + 方向）+ 每位置 2 个 `.f32` 文件
- 下载失败兜底：脚本支持传入本地 zip/目录路径（用户手动从 York 下载）
- README 加数据集出处与许可（Apache-2.0, University of York SADIE II）

### 2. `packages/renderer`
- **hrtf.ts**：清单格式升级为每位置 `{dry, wet}` 文件对；加载后按模式权重混合成每总线一条 IR：`IR = (1-w)·HRIR + w·BRIR`（时域对齐混合，离线原始 f32 缓存起来，切模式只重算混合不用重新下载）；IR 采样率 ≠ ctx 采样率时线性重采样
- **renderer.ts**：
  - 双耳图固定走 ConvolverNode（IR 必有，删掉 PannerNode 兜底分支）
  - 新增 `setBinauralMode(mode: "near"|"mid"|"far")`：按预设权重重混每总线 IR 并 `conv.buffer = ...`（可播放中切换）
  - 距离模型换苹果 inverse 定律：`gain = ref / (ref + rolloff·(d−ref))`，ref 按模式取 0.7/1.2/2.5m（ADM 归一化距离 × ref 得米制距离）
  - `applyGains` 时按源距离计算空气吸收低通系数，随 gains 消息一并发给 worklet
- **worklet**：每源加一个一阶低通（`y += a·(x−y)`，系数近 1 时直通），模拟距离空气吸收（杜比 far cue 的高频衰减）

### 3. `packages/player`
- `init()` 存模式；`ensureStreamRate` 对齐采样率后（含无需重建的情况）调 `loadBinauralIrs` 加载 IR 注入 renderer（`setBinauralIrs(map)` + 重建输出图）
- 新增 `setBinauralMode()` 透传 renderer，支持播放中切换

### 4. `apps/web`
- 顶栏在双耳模式下显示「距离：近/中/远」选择器（杜比 Binaural Settings 语义，默认「中」）
- 切换实时生效（不中断播放）

### 5. 文档
- 更新 `docs/binaural-rendering.md` 为最终实现（该文档原本就规划了这个架构）
- README 关键技术决策一节补充苹果/杜比文档依据 + SADIE II 许可说明

## 明确不做（本期范围外）
- 头部追踪（桌面无 IMU；苹果做法是世界锁定，未来可接 WebXR/DeviceOrientation）
- 立体声内容的上混虚拟化（苹果 Spatialize 的 stereo→5.1 上混，属于内容增强不是渲染器职责）
- 每源直达 HRTF（绕过 VBAP 直接卷积）：64 源 × 立体声卷积太贵，VBAP→BRIR 是杜比监听管线的标准做法
